Core graph node types plus enrichment-specific graph nodes, organized by logical group.

**Video game contract synchronized September 8, 2026:** [six game node families, reused endpoints, properties and image examples](#video-game-nodes). These are Go/GCP build contracts, not deployed game writers.

Most product graph nodes carry the base label **`Entity`** plus one or more type-specific labels. Legacy non-`Entity` labels are called out in the [Master Label List](#master-label-list). Nodes are created during the person and company get-add pipelines, funding ingestion, IMDB credit processing, expertise identification, and MusicBrainz waterfall enrichment.

<Note>
  **Existing-writer audit: 2026-07-09** — the original inventory describes the legacy graph writers. **Theatre contract synchronized: 2026-09-07** — [the four theatre node shapes](#theatre-nodes) and their properties are a Go development specification, checked against primary source pages and current `orbiter-universe` ownership patterns. The eleven direct-credit SQL tables now exist in development AlloyDB; theatre graph writers remain unbuilt. This pass does not re-audit the rest of the legacy inventory.
</Note>

## Master Label List

This is the canonical label inventory for node label combinations used by the documented writers, plus explicitly marked proposals. It includes both full create-label shapes and subset / match-only label combinations such as `Person`, `Company`, `Film_TV`, or `Work`. Dynamic families are shown with the controlling source field. **A proposed row reserves vocabulary; it does not assert that a writer or node exists.**

<Note>
  `Entity` is the intended base label for graph entities. A few older writers still create legacy non-`Entity` nodes (`Funding_Round`, `Project`, `Honor`, `Film_TV_Award:*`); they are listed here because they still appear in live or documented Cypher.
</Note>

## People

Nodes representing individual humans. A Person node may carry additional labels based on their role.

### Person

The core node for any individual in the graph.

<Card icon="circle-plus">
  ```text
  mvp/node/add-person-node — 2601
  ```

  **Creates** the Person node (`MERGE` on `master_person_id`, adds the `:Entity` label). Stamps `created_at` and `updated_at`. ✅
</Card>

<Card icon="pen-to-square">
  ```text
  mvp/node/update-person-node — 2758
  ```

  **Updates** the Person node (v1.11, 2026-07-09) — refreshes properties including bios, investor fields, and a scalar `linkedin_url` (v1.10); dual-writes `name_embedding` \+ Gemini `embeddings`. Stamps `updated_at`. ✅ _Note: the dynamic `:Angel` / `:C_Suite` label writing was lost in the v1.8 rebuild and is not restored — `:Angel` is stamped by #12702 only._
</Card>

<Card icon="circle-check">
  ```text
  mvp/imdb/run-base-imdb-person-enrich — 12880
  ```

  Flips `visibility` to `true` during IMDB enrichment — `SET p.visibility = true, p.updated_at = timestamp()`. ✅ Bumps `updated_at` (fixed 2026-06-01).
</Card>

| Property | Type | Description |
| --- | --- | --- |
| `uuid` | string | Primary identifier (UUID v4) |
| `master_person_id` | integer | The MERGE key — FK to Xano `master_person.id` |
| `name` | string | Full display name |
| `display_label` | string | Always `"Person"` |
| `visibility` | boolean | Whether the node is visible in the UI (starts `false`; flipped by the phase-11 finalizer) |
| `linkedin_url` | string | Canonical LinkedIn URL (stamped by #2758 v1.10) |
| `short_biography` / `long_biography` | string | One-line Cypher-safe projections of the Xano bios (control characters stripped) |
| `image_url` / `avatar` | string | Avatar URL where synced |
| `name_embedding` | vecf32 | OpenAI 1536 semantic embedding |
| `embeddings` | vecf32 | Gemini 1536 embedding (dual-write since 2026-06-15) |
| `created_at` / `updated_at` | timestamp | Epoch-millis `timestamp()` (nodes created before mid-2026 may carry ISO strings) |

<Accordion title="Real example">
  ```json
  {
    "uuid": "cf64fc2a-4b3e-4ff9-99dc-21d7cffebf01",
    "name": "Josh Diamond",
    "display_label": "Person",
    "visibility": true,
    "created_at": "2025-01-15T10:32:45.000Z"
  }
  ```
</Accordion>

### Angel

An additional label applied to Person nodes identified as angel investors.

<Card icon="tag">
  ```text
  mvp/fundable/resolve-investors-edges — 12702
  ```

  **Adds** the `Angel` label — `SET p:Angel` on the angel lead/non-lead investor branches during the company-side deal cascade. Stamps `updated_at`. ✅ _(The former #2758 `is_angel`-driven label write was lost in its 2026-07-05 rebuild; #12702 is the only live `:Angel` writer today.)_

**Labels:** `Entity:Person:Angel`

No additional properties beyond Person — `Angel` is a label-only modifier used for filtering and traversal.


  _Node labels: `Entity`, `Person`, `Angel`_
</Accordion>

## Organizations

Nodes representing companies, schools, VC firms, and other organizations. All share the same creation function (`mvp/node/add-company-node` #2602) with a dynamic label based on type.

### Company

The default organization node type. Represents businesses, startups, and corporations.

<Card icon="circle-plus">
  ```text
  mvp/node/add-company-node — 2602
  ```

  **Creates** the Company node — `CREATE (p:{nodeLabel} {...})` with a dynamic label (`Company`, `School`, etc.). Stamps `created_at` (active v4 template). ✅
</Card>

<Card icon="pen-to-square">
  ```text
  mvp/node/update-company-node — 4659
  ```

  **Updates** the Company node — refreshes enrich properties. Stamps `updated_at`. ✅
</Card>

<Card icon="pen-to-square">
  ```text
  tool/resync-company-node-domains — 13062   ·   tool/backfill-strip-domain-errors-nodes — 13060
  ```

  Maintenance tools that rewrite `company_domain` / `logo` on the Company node. Both stamp `updated_at`. ✅
</Card>

<Card icon="circle-check">


  Folds duplicate Company nodes during dedup (`SET` survivor properties). ✅ Bumps `updated_at` on the survivor (fixed 2026-06-01).

**Labels:** `Entity:Stage_Production`, optionally `:Play` or `:Musical`.

**Canonical Go type:** proposed `stage_production`.

**Identity:** one source-defined credited production/engagement. Separate Broadway, West End and revival engagements retain separate identities. A venue rename or corrected opening date does not create a new production.

**Proposed ownership:** entities owns identity; stage owns source/control records; facts owns the elected `stage_production_profile`; stage graph sync owns projection. Required in the direct-credit release.

In addition to the shared envelope:

| Property | Type / requirement | Source basis and mapping rule |
| --- | --- | --- |
| `entity_type` | string · R | Graph constant `Stage_Production`; SQL/API canonical type is `stage_production`. Never a film/music dispatch type |
| `title` | string · R | **D/B/L/O/S** production heading; `name` mirrors the elected title |
| `form` | enum · O | **B/L/O** → `play`, `musical`, `other`; unknown is absent. Only the first two add subtype labels; retain unmapped source wording in evidence. |
| `market` | enum · R for initial scope | **D/B/L/O/S** verified engagement → `broadway` or `west_end`. London address alone does not establish West End scope; other engagements remain discovery context until approved. |
| `production_kind` | enum · O | **B/L/O** explicit `original`, `revival`, `return_engagement`, or `other`; do not infer from title or award category alone |
| `ibdb_production_id` | string · O | **B** validated numeric production ID, projected from the typed alias registry; e.g. Outsiders Broadway `537824` |
| `broadwayworld_show_id` | string · O | **D** literal numeric `showid` (Cabaret example: `334560`), admitted as a production alias only after exact engagement review. Keep links/party IDs in their own typed source records. |
| `wikidata_id` | string · O | **W** QID only when the item identifies this exact production/engagement. A work-level QID belongs on `Theatrical_Work`, not here. |
| `official_website_url` | URL string · O | **O**, or a verified outbound link from **B/L/T**; confirm the page refers to this engagement rather than only its tour |
| `season_label` / `season_scheme` | string, string · O together | Source-labelled season when supplied; otherwise a versioned Orbiter market-specific calculation. Keep its derivation; never assume award year equals production season. |
| `first_preview_date` | ISO date string · O | Explicit preview start from an approved production record/programme; not available on every **B/L/O** page |
| `opening_date` / `press_night_date` | ISO date string · O | **B/L/O**, corroborated by **T** where present; separate opening from UK press night when source semantics differ |
| `announced_closing_date` | ISO date string · O | **L/O** or an explicit **B** announcement; future/planned end, not evidence the show already closed |
| `closing_date` | ISO date string · O | **B/L/O** accepted evidence that the last performance actually occurred; remains absent for an open run |
| `booking_until_date` | ISO date string · O | Only a source explicitly identifying its sales horizon. Last selectable ticket date is not a closing date. |
| `run_status` / `run_status_as_of` | enum, ISO date string · O together | `announced`, `previews`, `running`, `suspended`, `closed`, `cancelled`; selected source status or documented derivation with an as-of date. No automatic close from a stale booking deadline. |
| `running_time_minutes` | integer · O | **L/O** duration, normalized only when unambiguous; strictly positive |
| `runtime_includes_intermission` | boolean · O | **L/O** explicit inclusion statement; unknown remains absent |
| `intermission_count` / `intermission_minutes` | integer · O | **O** or programme explicitly supplies each value; absence does not mean zero |
| `age_recommendation_text` / `content_advisory_text` | string · O | **L/O** attributed audience guidance; optional display context, not an invented standardized rating |
| `work_entity_id` | UUID string · O | Resolved `theatrical_work` only; verified relation cache, never a title match. Missing work identity does not block credit intake. |
| `credit_coverage` | enum · R | Derived from scoped snapshots: `unknown`, `partial`, `provisional`, `complete`, `empty_confirmed`. A source's unfinished-credit notice prevents `complete`. This does not describe identity-resolution progress. |
| `accepted_credit_count` / `unresolved_mention_count` | integer · O | Derived from the same revision's credit ledger. Counts do not establish exhaustive coverage or capital participation. |

Preserve source date text and precision in the claim envelope. Only exact dates become `YYYY-MM-DD` graph values; a year or month is not padded into a fabricated day. A preview, press night, opening, announced end and confirmed final performance are distinct facts.

**Keep off the node:** producers belong in the credit ledger and accepted `PRODUCED` relationships, including literal billing, role, source group, evidence and any explicit credit dates. Venue associations belong in a dated SQL association list and the proposed `STAGED_AT` relationship, so a production can move without overwriting its history. Budgets, capitalization, recoupment and alleged investor amounts are outside this credit waterfall.

### Work:Theatrical_Work

**Labels:** `Entity:Work:Theatrical_Work`, optionally `:Play` or `:Musical`.

**Canonical Go type:** proposed `theatrical_work`.

**Identity:** the dramatic work shared by independently identified productions, with explicit edition/adaptation boundaries. It is separate from its source novel, film adaptation, musical score and cast recording.

**Proposed ownership:** entities identity, facts-owned `theatrical_work` cache, dedicated work projection. Optional v1 linking; defer creation if identity is not established.

| Property | Type / requirement | Source basis and mapping rule |
| --- | --- | --- |
| `entity_type` | string · R | Graph constant `Theatrical_Work`; SQL/API canonical type is `theatrical_work` |
| `title` | string · R | **O**, supported by **B/A** credit context; not sufficient by itself to merge productions into one work |
| `form` | enum · O | Explicit source classification → `play`, `musical`, `other`; same closed subtype rule as production |
| `wikidata_id` | string · O | **W** independently reviewed work-level QID (Outsiders work example: `Q125293293`); source statement provenance stays in SQL |
| `ibdb_show_id` | string · O | **W/B** verified show/work identifier, including P1219 with its reference (Outsiders work example: `537823`). Never substitute it for `ibdb_production_id`. |
| `original_title` | string · O | Official programme/work evidence explicitly distinguishes an original title; never reverse-translate |
| `language_codes` | string[] · O | Explicit work-language evidence, normalized to the agreed language vocabulary; a production's location or page language is insufficient |
| `edition_label` / `version_label` | string · O | Explicit credited adaptation/revision/translation designation; preserve conflicting editions for identity review |
| `first_produced_year` | integer · O | Explicit authoritative work history/programme; earliest production in our database is not proof of the world premiere |
| `setting_summary` | string · O | Source-supported dramatic setting, only when shown to belong to this work/version rather than a director's particular staging |
| `creator_display_names` | string[] · O | Derived display projection from accepted, role-qualified work creator claims; literal names, no inferred identities |
| `adaptation_summary` | string · O | **O/B/T/A** explicit source-material attribution, summarized with evidence; does not create or merge its underlying novel/film node |

**Source IDs:** Wikidata QIDs can supply typed work identity after review; P1219 supplies an IBDB **show/work** ID. The audit found Outsiders work `Q125293293` / show ID `537823`, distinct from Broadway production `537824`. Neither an external alias nor a production programme is a universal work-identity guarantee. Do not invent `ibdb_work_id`, reuse `ibdb_production_id`, or attach a score/recording MBID to the whole stage work. Preserve statement IDs, ranks, qualifiers, references and item revision in SQL, and hold disputed mappings for review.

**SQL/DTO-only creator claims:** `role` (`playwright`, `book_writer`, `composer`, `lyricist`, `adapter`, `translator`), literal billed party/group, optional canonical party ID, evidence and work-version scope. These roles are proposed mappings, not a requirement that every source supplies each one. Directors, cast, orchestrators and producing teams generally belong to production-specific credits unless explicit evidence establishes a work-level contribution. A role-qualified accepted relationship can later be projected under a separately reviewed edge contract.

Use family-qualified indexes and writer/retraction predicates. Shared `Work`, `Play` or `Musical` labels must never let theatre sync delete music nodes, or music sync rewrite theatrical works. Major adaptation/version identity questions stay in review; a renamed work does not automatically become a new entity.

### Place:Venue:Theatre

**Labels:** proposed `Place:Venue:Theatre`.

**Canonical Go type:** none in this slice; use the current support-place architecture.

**Identity:** one physical theatre or separately identified performance space, independent of its current name, owner and productions.

**Proposed ownership:** an owner-approved shared-place lookup/alias and support-replay seam. Reuse any existing music place and UUID. Until that seam exists, retain pending venue evidence rather than create duplicate places.

| Property | Type / requirement | Source basis and mapping rule |
| --- | --- | --- |
| `entity_type` | string · R | Existing support graph vocabulary `Place`; not a canonical `entities.entity_type` registration |
| `place_type` / `venue_type` | string, string · R | Proposed `Venue` / `Theatre`, supported by source description. These modifiers do not change the owner identity. |
| `ibdb_theatre_id` | string · O | **V** typed venue ID; separate namespace from IBDB production and party |
| `mbid` | string · O | Retained only from a verified existing music-place match; never generated from a name/address |
| `official_website_url` | URL string · O | **H/V/L** verified venue page |
| `address` | string · O | **V/H** source-rendered physical address, preserving the source wording in evidence |
| `street_address`, `city`, `region`, `postal_code`, `country_code` | string · O each | **H/V** explicit address components; normalize country codes only with evidence. Do not fill unknown components from guesses. |
| `latitude` / `longitude` | float · O together | Verified source-supplied coordinates or existing accepted place data; valid paired ranges. No new geocoding dependency is required. |
| `year_built` | integer · O | **V/H** explicit building year; distinguish it from opening or renaming dates |
| `seating_capacity` | integer · O | Selected **H/V** capacity claim; positive, qualified by basis and as-of evidence |
| `capacity_basis` | string · O, required with capacity | Source's configuration/approximation description; no silent averaging of conflicting totals |
| `capacity_as_of` | ISO date string · O | Source-stated effective date; keep absent if only fetch time is known |
| `stage_type` | string · O | **H** explicit physical stage specification, normalized only through an approved vocabulary |
| `accessibility_url` | URL string · O | Source-provided official accessibility information, when supplied; no capability inferred from a venue label |

**A real conflict to preserve:** the inspected IBDB venue page reports **1,078 approximate seats**, while the operator lists **1,092 total seats** with a seating breakdown. These observations motivate separate capacity claims with source, configuration and time. Prefer a current operator specification for its stated configuration; if configuration/effective-time equivalence is unclear, mark the dispute and do not represent either as an unqualified universal capacity. [IBDB venue](https://www.ibdb.com/theatre/bernard-b-jacobs-theatre-1346), [operator specification](https://shubert.nyc/theatres/bernard-b-jacobs).

**SQL/DTO-only history:** dated names, former names with unknown dates preserved as unknown, source-ID aliases, source capacity claims, and separate owner/operator/lease relationships with evidence and validity intervals. Do not turn an operator's company ID into the venue identity. A complex and one of its auditoria are not the same place solely because they share an address.

Adding the `Entity` label later would require a deliberate shared-place canonical-entity migration, preserving support UUIDs, existing music links and source aliases. It is not part of this stage proposal.

### Stage_Award

**Labels:** `Stage_Award`, optionally `:Nominee` or `:Winner`.

**Canonical Go type:** none; a proposed stage-owned support record and bounded support replay.

**Identity:** one award-body entry for a category/year and explicitly scoped production or recipient/group. It is not an award ceremony or a generic category node. A win updates the same nomination-entry identity. This is a deliberate theatre-specific contract: the current movie award writer includes outcome in identity and cannot be reused unchanged.

| Property | Type / requirement | Source basis and mapping rule |
| --- | --- | --- |
| `entity_type` | string · R | Proposed support graph vocabulary `Stage_Award`; no automatic canonical entity admission |
| `awarding_body` / `awarding_body_key` | string, string · R | **T/A** public series name plus controlled namespace, initially `tony` or `olivier` |
| `award_year` | integer · R | **T/A** award edition year, independently of the production's opening year |
| `category_name` | string · R | **T/A** category label with its original sponsor wording retained in evidence |
| `category_key` | string · R | Orbiter-controlled, body-scoped category mapping; version renames/sponsor changes rather than silently combining different categories |
| `outcome` | enum · R | **T/A** explicit `nominee`, `winner`, or `honoree`; never infer winner from promotional copy lacking scoped evidence |
| `result_scope` | enum · R | `production`, `person`, `company`, or `joint`, derived from the actual entry's recipient definition |
| `source_award_entry_id` | string · O | Only if an adapter verifies a durable award-entry ID. Otherwise use a reviewed scoped registry key; not an HTML list position or recipient-name hash. |
| `production_entity_ids` | UUID string[] · O | Resolved exact engagements explicitly associated with the award entry; can include several only when the source entry itself does |
| `recipient_entity_ids` | UUID string[] · O | Only explicitly named and resolved recipients. A production win does not populate this with its whole producer list. |
| `recipient_display_names` | string[] · O | Literal source recipients, derived from the recipient ledger; retain unresolved groups without pretending they are individual IDs |
| `production_titles` / `venue_names` | string[] · O | Source context for identifying the correct engagement; titles and venues are not strong identity keys |
| `citation_summary` | string · O | Permitted summary of the **T/A** award citation; exact source text remains in the snapshot |
| `ceremony_date` | ISO date string · O | Official award-series announcement when explicitly supplied; do not infer it from year or source fetch time |

`name` is a deterministic display projection of body, year, category and entry subject; it is not the identity key. Store **SQL/DTO-only** entry history, recipient groups/members, nomination and winner observations, production associations and their resolution states. Keep one durable result row when a nomination becomes a win; the current `Winner` label replaces `Nominee`, while nomination history remains. Special honorees need no subtype label unless a future contract approves one.

Award nodes may retain unresolved source context for discovery/admin use, but public recipient/production edges require resolved endpoints. Two separate entries for one person in the same year/category and different productions stay distinct; a genuinely joint entry stays one result with explicit members. Do not conflate a score/book award with ownership of the entire theatrical work.

### Relationships and release boundary

The [closed build output manifest](/guides/open-work/roadmap/broadway-co-producers#theatre-graph-output-manifest) links every owned/reused node and all ten relationship families to these examples. Only the production hub and direct `PRODUCED` edges are mandatory in v1.

| Proposed connection | Ownership and limit |
| --- | --- |
| `Person/Company → PRODUCED → Stage_Production` | First-release direct-credit backbone, using the plan's agreed role weights and evidence envelope |
| `Stage_Production → PRODUCTION_OF → Theatrical_Work` | Optional resolved work context; proposed weight 50, excluded from scoring |
| `Stage_Production → STAGED_AT → Place:Venue:Theatre` | Dated support-place association; proposed weight 50, excluded; shared-place ownership required |
| `Theatrical_Work → ADAPTED_FROM → resolved source work` | Later explicit adaptation evidence; proposed weight 55, excluded; no `SAME_AS` shortcut |
| `Person/Music_Group → WROTE/COMPOSED/WROTE_LYRICS → Theatrical_Work` | Explicit work-level roles; proposed 10/8/12 using music precedents, excluded initially |
| `Stage_Production → HAS_AWARD → Stage_Award` | Production/associated-recipient context; proposed weight 40, excluded initially |
| `Explicit Person/Company → WON_AWARD/NOMINATED_FOR → Stage_Award` | Only named recipients; proposed 30/35, excluded initially; a production result is not copied to its producers |

A shared work or venue must not create the same relationship strength as co-producing **the same production**. The [theatre edge contracts and property examples](/guides/ontology/edges#theatre-edges), [proposed weights](/guides/ontology/edge-weights#theatre-weights) and [Go build plan](/guides/open-work/roadmap/broadway-co-producers#proposed-theatre-node-types) are aligned documentation. The direct-credit SQL tables exist; runtime type registration, endpoint dispatch, scoring filters and API registration remain unbuilt. Optional work/venue/award storage still belongs to its respective build slice; context graph writes stay disabled until their reader exclusions are verified.

Individual showings are deferred. A future `Entity:Event:Theatre_Performance` could represent a dated performance if attendance/ticketing requires it, but it is **not added to the reserved label inventory or v1 work**. People and producing companies retain their existing canonical types.

Before implementation, freeze the property/identifier enums and minimum fixture coverage; register both canonical types through admission, queues, facts, distill, graph sync, publish, merge and repair; define support-place/result ownership; and test cross-feature replay and corrections. These are development requirements, not changes performed by this documentation pass.

### MediaAppearance

One source-identified episode or session, independent of the sites/assets distributing it. A publisher podcast episode and an explicitly equivalent video share one canonical identity. A show, channel, conference edition, clip and news article are different things. Do not key this node by title/date/host set or use a show-level URL as an episode ID.

**Proposed upsert identity:** canonical `entity_id`; `uuid` remains the stable graph UUID. Typed source aliases are resolved through `entity_identifiers` and the media source-association owner. Review these keys before implementing the writer. YouTube video IDs are case-sensitive; RSS GUIDs are exact and feed-scoped; conference session IDs are organizer/edition-scoped. Compilation assets map to scoped segments in SQL and are not single-appearance strong aliases. Source identity and retention rules are in the [build contract](/guides/open-work/roadmap/media-co-occurrence#identity-node-types-and-cross-source-deduplication).

<a id="music-standard-node-envelope" />

### Standard Music Node Envelope

```cypher
MERGE (n:<labels> {mbid: $mbid})
SET n.uuid           = coalesce(n.uuid, randomUUID()),
    n.display_label  = "<Label>",
    n.visibility     = true,
    n.description    = <good <=127 summary | null>,
    n.name_embedding = vecf32($embedding),
    n.embeddings     = vecf32($geminiEmbedding),
    n.created_at     = coalesce(n.created_at, timestamp()),
    n.updated_at     = timestamp()
    // node-specific properties, plus image_url where supported
```

| Field | Type | Required | Notes |
| --- | --- | :-: | --- |
| `uuid` | string | Yes | `randomUUID()`, stable via `coalesce` |
| `mbid` | string | Yes | MusicBrainz ID and MERGE key |
| `display_label` | string | Yes | Product-facing label |
| `visibility` | boolean | Yes | UI flag |
| `description` | string/null | Yes | GOOD-or-null invariant: one clean factual sentence \<=127 characters beginning with the entity name, or exactly `null` |

<a id="music-genre-policy" />

### Music Genre Policy

Genres are metadata properties on music nodes, not graph nodes.

Do not create `Entity:Genre` nodes or `HAS_GENRE` edges. Keep genre values on the source music node as normalized `genres` metadata so the product can use them as facets, filters, badges, search text, or side-panel context without turning every genre into a first-class entity.

<a id="music-media-image-url" />

### Music Media (`image_url`)

Three node types can carry a re-hosted image on `image_url`, matching the `film_tv.image_url` convention. The value is the GCS-hosted WebP URL, not the raw external URL. When no image is found, the property is explicitly set to `null`.

| Node | Source field | GCS path | Raw source |
| --- | --- | --- | --- |
| `Recording` | `mb_recording.gcp_cover_art_url` (#738) | `music-cover-art/<mbid>.webp` | Cover Art Archive |
| `Music_Group` | `mb_artist.gcp_music_group_image_url` (#737) | `music-group-image/<mbid>.webp` | serper.dev image search |
| `Person:Music_Artist` | `mb_artist.gcp_person_avatar_url` (#737) | `music-person-avatar/<mbid>.webp` | serper.dev image search |

Image writers are `mb/media/fetch-recording-cover-art` (#13108), `mb/media/fetch-group-image` (#13109), and `mb/media/fetch-person-avatar` (#13120). After the GCS URL is stamped on the source row, Cypher updates the node's `image_url`. The already-done path self-heals existing nodes.

## Timestamp coverage audit

The historical writer convention is `created_at` set in the create/`ON CREATE SET` clause and `updated_at` set in the update/`ON MATCH SET` clause — both as Cypher `timestamp()` (epoch-millis). **The July audit reported both stamps for the legacy types it covered** — the gaps found by the 2026-06-01 sweep were all patched (creators that omitted `created_at`: Country, SubDomainExpertise, Event:Live\_\*, Certification, Honor, Project, Publication, Organization; updaters that omitted `updated_at`: the IMDB visibility flip #12880, the company dedup fold #10505, the VC\_Firm / Organization label-adds, and the certification `SET`). The proposed theatre nodes are not implemented and have no timestamp-coverage claim; their future timestamp requirements are specified in the shared theatre envelope above.

<Note>
  **Known remaining gaps** (outside the enrichment pipelines' documented types): `contextFounded` (`mvp/yc/process-yc-people` #12700) sets no `created_at` on the hub node, and the `Document`/`DocumentChunk` (`#12850`, `#4596`) and user/organization-graph types `MasterPerson` / `MasterOrganization` (`#12869`, `#12884`) remain unstamped. The `qa/resolve-edges-*` functions (#12715/#12718/#12719) are QA mirrors of the production resolvers — patch them alongside if QA parity matters.
</Note>
