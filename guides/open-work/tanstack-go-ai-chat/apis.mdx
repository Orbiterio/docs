<Warning>
**Snapshot 2026-09-14 — Xano workspace 3, group `Tanstack AI Chat` (ID 1286, canonical `6TC-_sTf`).** Of 48 endpoints, **15 are implemented** and **33 are Phase-2 contract shells** returning `NOT_IMPLEMENTED`. Status is marked per endpoint.
</Warning>

Proposed Go routes follow orbiter-backend conventions: `/v1/` prefix, `{data, error, meta}` envelope, `RequireWorkOS` auth, owner from session. The `suggestions` and `relationships` features already exist on `main` — request/result endpoints extend `suggestions` (`suggestions.suggestion_request`, Xano name kept) and `relationships`; the remaining surface is a proposed `copilot` feature for threads/messages. See [table mapping](/guides/open-work/tanstack-go-ai-chat).

<Info>
**Name collision:** Xano "outcomes" (suggestion requests/results) is not the Go `outcomes` feature (`outcomes.investment_theses` = investor profiles). Chat outcome endpoints are proposed under `/v1/copilot/outcomes/*` to keep them out of that feature.
</Info>

## Threads — shared transport

The thread endpoints serve every surface. `thread_id` carries a surface prefix (`meeting_prep:<key>`, `leverage_loops:<request_id>`, `outcomes:<request_id>`) that the handler parses to route messages into the right transcript table.

### Existing Xano APIs

| Endpoint | What it does | Tables | Status |
| --- | --- | --- | --- |
| `POST /threads/ensure` | Find-or-create a `conversation` row by surface + thread key | `conversation` R/W | Implemented |
| `GET /threads` | List the user's threads | `conversation` R | Shell |
| `GET /threads/{thread_id}/messages` | Hydrate messages — resolves surface from `thread_id`, queries the matching transcript table | `conversation` + `copilot_chat_messages` / `leverage_loop_conversations` / `outcome_conversations` R | Implemented |
| `POST /threads/{thread_id}/messages` | Append messages; dedupes on (request, role, content) before insert; creates the surface conversation if missing | `conversation` R/W + transcript tables R/W | Implemented |
| `PATCH /threads/{thread_id}` | Rename / archive thread metadata | `conversation` W | Shell |
| `DELETE /threads/{thread_id}` | Delete/archive a thread | `conversation` W | Shell |

### Proposed Go spec — `internal/features/copilot`

| Route | What it should do | Tables |
| --- | --- | --- |
| `POST /v1/copilot/threads/ensure` | Find-or-create by (`user_id`, `surface`, `surface_key`) — no prefix parsing; caller passes structured fields | `copilot.conversations` R/W |
| `GET /v1/copilot/threads` | Paginated list, optional `surface` filter | `copilot.conversations` R |
| `GET /v1/copilot/threads/{id}/messages` | Cursor-paginated messages via `conversation_id` — one table regardless of surface | `copilot.conversations`, `copilot.messages` R |
| `POST /v1/copilot/threads/{id}/messages` | Append batch of messages; service-layer dedupe; owner check via conversation | `copilot.conversations` R/W, `copilot.messages` R/W |
| `PATCH /v1/copilot/threads/{id}` | Update `title`/`archived_at` | `copilot.conversations` W |
| `DELETE /v1/copilot/threads/{id}` | Soft-delete/archive (200 + null-data envelope) | `copilot.conversations` W |

## Leverage Loops (`leverage_outcome`)

<Info>
**Renamed flow.** These endpoints are the `leverage_outcome` mode — an outcome request *for a specific person* ("I want to help Katelyn hire a chief of staff"), carrying a beneficiary `master_person_id`/contact. `POST /leverage-loops/interview` is that mode's interview; `leverage_loop` itself has no AI chat, only a button. See [Migration Planning](/guides/open-work/tanstack-go-ai-chat/migration-planning).
</Info>

## Notes

- Four `api.request` calls to OpenRouter (`/chat/completions`) across the interview endpoints — the Go rebuild puts these behind the platform LLM client, not inline handlers.
- Shell endpoints have full input contracts in Xano already — the Go DTOs can be generated from them nearly 1:1.
- `threads/{id}/messages` POST is the only multi-table writer: conversation ensure + per-surface transcript dedupe/insert. In Go this becomes one service method over `copilot.conversations` + `copilot.messages`.
