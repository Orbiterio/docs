This is a hand-written **Outcome** demo package for the seed-raise use case: six NYC-based angel investors, all `ready`, each carrying a WHY narrative and four hooks: three written opening lines and one generated `hook_remix`. It follows the same load path as [Create Demo Suggestions](/guides/open-work/suggestion-delivery-and-tables/create-demo-suggestions): the package loads through `cmd/ingestpackage`. All entity and scope IDs below are already resolved against dev AlloyDB.

<Warning>
**The `POST /v1/ingest/suggestions` receiver described in [Suggestion Delivery and Tables](/guides/open-work/suggestion-delivery-and-tables) was not built.** This package loads with the backend CLI (`cmd/ingestpackage`) as is: the JSON below is byte-for-byte the backend's acceptance fixture `internal/features/suggestions/testdata/angel_outcome.package.json`, which the test suite decodes strictly, validates, stores and reads back. Entity types are table names (`persons`, `companies`). Batch scope (organization, requester, suggestion type, origin) is not in the package; it comes from the request record below and the CLI flags.
</Warning>

## Package

One `outcome` package holding all six `ready` suggestions. Trajectories, sequencing, paths and evidence stay empty for this demo; each suggestion carries one cold `draft_email` action (see [Email actions](#email-actions)). The [Outcome sample](/guides/open-work/suggestion-delivery-and-tables/sample-suggestion-data#outcome) shows the warm pattern. Every hook references the suggested person and repeats that person's `entity_type`.
