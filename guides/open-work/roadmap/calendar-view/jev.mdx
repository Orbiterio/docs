## Assessment

The calendar mirror, date math, availability, permissions, queue, SSE, layout and
ordinary interactions have **no useful JEV role** in this plan. They stay in
code and provider contracts, and work with Akira and JEV unavailable.

Two optional assistant experiments are now scoped on the dedicated
[Akira JEV page](/guides/open-work/roadmap/akira/jev):

- **J01 — Calendar intent:** classify a supported simple operation, compound
  request or unknown intent. This is a future pilot after an Akira baseline
  dispatcher exists; the existing scoped outcome classifier is only a reuse
  candidate.
- **J02 — Evidence support:** check whether supplied sources establish one
  generated meeting-context claim. This requires the approved UUID context
  adapter and claim-level provenance; it creates no facts or identity links.

Akira is **spec only, not implemented**. Its
[calendar capability](/guides/open-work/roadmap/akira/calendar) owns the proposed
five tools and their acceptance criteria. The original Calendar phase 6 prompt
remains preserved as supplied material, with the prerequisite explained above it.

## NL Date Picker extension

The new [NL Date Picker spec](/guides/open-work/roadmap/calendar-view/nl-date-picker#jev) adds **J03: select a supplied date mention by semantic role**, such as reminder time versus meeting time. A local parser must first admit the candidates; Temporal owns resolution and validation. This optional component pilot is independent of Akira and does not classify dates for arithmetic, resolve genuine ambiguity or authorize a write.

J03 has a separate disabled-by-default flag, unset threshold, synthetic request/response example and evaluation gates on that page. The component can ship with local parsing and manual controls alone.

## Build implications

Phase 0 decides whether either experiment has a viable seam and measurable
benefit. Phases 1–4 have no classifier dependency. Phase 5 may evaluate J02 after
the context contract exists; Phase 6 is an Akira integration task after its
foundation is implemented. Phase 7 reports quality, latency and total cost
separately from the nine calendar performance gates.

Both pilots remain disabled, thresholds unset and results unmeasured. Detailed
requests, synthetic responses, unknown/error behavior, evaluation datasets and
adoption gates live in [Akira's JEV spec](/guides/open-work/roadmap/akira/jev).
The handoff bundle's `JEV.md` is a snapshot of that canonical spec.
