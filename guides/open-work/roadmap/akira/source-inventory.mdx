## The misleading handoff name

The inspected `handoff_to_akira` definition describes an **unsupported-request exit**: it commits a handoff record and a deterministic closing message, then ends the outcome intake. Its handler submits a `kind: handoff` context effect. No receiving Akira executor was identified in that inspected path.

Therefore, seeing that tool name is not evidence that a separate Akira assistant is running. Before a real handoff exists, define the destination runtime, accepted payload, correlation/ownership, acknowledgement, cancellation, failure behavior and user-visible status. Do not present an unsupported exit as completed delegation.
