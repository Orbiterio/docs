**Status: candidates verified against dev AlloyDB + ProPublica on 2026-09-06; nothing run yet.** This page is the smoke-test contract for the [Phase 1 990 adapter](/guides/open-work/roadmap/990-fec-form-d/phase-1-990-adapter). The point of the set is not "does it run" — it is **does the graph hold more, and correct, data afterwards than before.** Every fixture therefore comes with a measured *before* baseline, and the pass criteria assert the *delta*.

<Info>
**How the candidates were chosen.** Queried the dev `orbiter_universe` AlloyDB (read-only, IAP tunnel) for (a) `company` entities with a graph node whose name is foundation-shaped or whose Fundable mirror is `non_profit`, (b) `master_companies.is_school` rows, and (c) `person_work_experience` rows whose title matches `trustee | board member | foundation` **and** whose `company_entity_id` resolved to an org that is already in the graph. Each survivor was checked against the ProPublica Nonprofit Explorer API for an EIN and for e-filed 990s with data in TY2020–2023. The dev FalkorDB is IP-restricted, so "graph edges" below are read from the relational ledgers that mirror it (`entities.graph_node_uuid`, `person_education.graph_written_at`, `person_work_experience.graph_written_at`). Re-run the baseline queries at the bottom before the first real drain — counts move as the person waterfall runs.
</Info>

## Before-baselines (run first, keep the output)

```sql
-- the three affiliation fixtures: org node + the board member's current link to it
SELECT mc.name AS org, e.id AS org_entity, e.graph_node_uuid IS NOT NULL AS org_has_node,
       mp.name AS person, pe.id AS person_entity, pe.graph_node_uuid IS NOT NULL AS person_has_node,
       pw.title, pw.graph_written_at IS NOT NULL AS works_at_edge_exists
FROM universe.master_companies mc
JOIN universe.entities e  ON e.id = mc.entity_id AND e.merged_into IS NULL
JOIN universe.person_work_experience pw ON pw.company_entity_id = e.id AND pw.title ~* '(board|trustee)'
JOIN universe.entities pe ON pe.id = pw.entity_id
JOIN universe.master_persons mp ON mp.entity_id = pe.id
WHERE mc.domain IN ('veteransfuture.org','hpaonline.com','californiasciencecenter.org')
   OR mc.name IN ('Veterans Future Foundation','Hollywood Professional Association','California Science Center Foundation');

-- the School fixtures: existing inbound edges (ATTENDED / WORKS_AT) as the "before" number
SELECT mc.name, e.id, e.graph_node_uuid,
  (SELECT count(*) FROM universe.person_education pe WHERE pe.school_entity_id = e.id AND pe.graph_written_at IS NOT NULL) AS attended_edges,
  (SELECT count(*) FROM universe.person_work_experience pw WHERE pw.company_entity_id = e.id AND pw.graph_written_at IS NOT NULL) AS works_at_edges,
  (SELECT count(*) FROM universe.entity_facts f WHERE f.value_entity_id = e.id AND f.is_chosen) AS inbound_chosen_relation_facts
FROM universe.master_companies mc JOIN universe.entities e ON e.id = mc.entity_id
WHERE e.merged_into IS NULL AND mc.domain IN ('stanford.edu','nyu.edu','harvard.edu');

-- Ford: must be absent from Universe and present in the Fundable mirror
SELECT (SELECT count(*) FROM universe.entity_identifiers WHERE kind = 'ein' AND normalized_value = '131684331') AS universe_ein_rows,
       (SELECT id FROM fundables.organizations WHERE domain = 'fordfoundation.org') AS fundable_org_id;
```

Measured 2026-09-06: VFF / HPA / CSC each have the org node, the person node, and one `WORKS_AT` edge with a board title; Stanford 24 / NYU 11 / Harvard 12 `ATTENDED`; **0** inbound chosen relation facts on any School; Ford `universe_ein_rows = 0`.

## ST-2 — Stanford: School label, double roles, Schedule I (F4)

**Input:** `POST …/orgs {"ein":"94-1156365","years_window":4}`, one drain.

**Expected:** the org resolves to the **existing** `School` entity — `ResolveStrong("ein")` finds nothing, the soft `name` candidate is **not** auto-picked (soft keys nominate, never decide), and the **domain corroboration** step (below) finds `stanford.edu` as an existing strong `domain` key → the EIN is attached to that entity. Once linked: `MergeCompany` adds `Organization` **add-only** (labels after: `School`, `Company`, `Organization`, `Entity`), `nonprofit: true`. ≥ 1 mention with both `IndividualTrusteeOrDirectorInd` and `OfficerInd` → two ledger rows for that person (8 and 14). Schedule I rows ≥ 200 with `recipient_ein` populated on most. The 24 `ATTENDED` edges are untouched. Roles come from **flags**, not the dictionary (`role_source = flags` on every Form 990 row).

<Note>
**Decided 2026-09-06 (Mark) — Q6 on the adapter page.** The three School fixtures already exist as entities keyed by `domain`, and the 990 filer name rarely equals the display name ("The Board of Trustees of the Leland Stanford Junior University"), so `ResolveStrong("ein")` misses and D4 correctly refuses the soft-name match — as originally spec'd the adapter would mint a **second** Stanford. Ruling: **(b) the org step corroborates through the domain** — ProPublica's `website` for the EIN (fallback: the filing's `WebsiteAddressTxt`) is reduced to its registrable domain and looked up as an existing **strong `domain` identifier**; a hit means the EIN is attached to *that* entity. This *finds* by domain, never *mints* one (the mirror of open Q2). **(a) hand-seeding `ein` onto the fixture School entities is the Phase 0 fallback** if the website field is too dirty on the fixture set.

**Phase 0 measured it (2026-09-06):** ProPublica's `website` is **empty for all eight fixtures**, while the filing's own `WebsiteAddressTxt` is populated on every one — `WWW.STANFORD.EDU`, `WWW.NYU.EDU`, `WWW.HARVARD.EDU`, `VETERANSFUTURE.ORG` (but `WWW.FITOPS.ORG` on VFF's TY2022 filing, before the rename), `WWW.HPAONLINE.COM`, `WWW.CALIFORNIASCIENCECENTER.ORG`, `WWW.FORDFOUNDATION.ORG`, `WWW.CEDARS-SINAI.ORG`. So the source order is the **latest filing's `WebsiteAddressTxt` first**, ProPublica as the fallback, and the `ein_preseeded` fallback is not needed for this set. Stanford/NYU/Harvard registrable domains equal the existing School entities' `domain` keys exactly. Assert in ST-2: `org.reused_existing_entity = true`, `org.resolution_method = "domain_corroboration"` (or `"ein_preseeded"` under the fallback), and the fixture-duplicate acceptance query returns zero rows.
</Note>

## Acceptance queries (zero rows required, run twice)

```sql
-- role/edge kind mismatch
SELECT id FROM universe.filing_990_governance_edge
 WHERE edge_kind = 'OFFICER_OF' AND role NOT IN ('officer','key_employee');
-- weight outside the decided set
SELECT id FROM universe.filing_990_governance_edge
 WHERE (edge_kind='BOARD_MEMBER_OF' AND weight <> 8)
    OR (edge_kind='OFFICER_OF' AND weight NOT IN (14,20));
-- edge with no chosen fact behind it
SELECT e.id FROM universe.filing_990_governance_edge e
 LEFT JOIN universe.entity_facts f ON f.id = e.fact_id AND f.is_chosen
 WHERE e.graph_written_at IS NOT NULL AND f.id IS NULL;
-- open valid_to on a person absent from the org's latest filing
SELECT e.id FROM universe.filing_990_governance_edge e
 WHERE e.valid_to IS NULL AND NOT EXISTS (
   SELECT 1 FROM universe.filing_990_governance_mention m
   JOIN universe.filing_990 f ON f.id = m.filing_id
   WHERE m.person_entity_id = e.person_entity_id AND f.org_entity_id = e.org_entity_id
     AND NOT m.is_former
     AND f.tax_period = (SELECT MAX(tax_period) FROM universe.filing_990 WHERE org_entity_id = e.org_entity_id));
-- person minted by this lane without a strong identifier
SELECT en.id FROM universe.entities en
 JOIN universe.enrichment_queue q ON q.entity_id = en.id AND q.source_function = 'filings.irs990'
 WHERE NOT EXISTS (SELECT 1 FROM universe.entity_identifiers i WHERE i.entity_id = en.id AND i.is_strong_identity);
-- filing without its verbatim XML
SELECT id FROM universe.filing_990 WHERE xml_storage_key IS NULL OR xml_sha256 IS NULL;
-- a second entity for a fixture org (the ST-2 trap): more than one company holding a fixture EIN OR domain
SELECT i.normalized_value, count(DISTINCT i.entity_id) FROM universe.entity_identifiers i
 JOIN universe.entities e ON e.id = i.entity_id AND e.merged_into IS NULL
 WHERE i.kind IN ('ein','domain') AND i.normalized_value IN
   ('821433446','260017646','952210527','941156365','135562308','042103580','131684331',
    'veteransfuture.org','stanford.edu','nyu.edu','harvard.edu','fordfoundation.org')
 GROUP BY 1 HAVING count(DISTINCT i.entity_id) > 1;
```

```cypher
// edges missing the envelope or the ontology's provenance set
MATCH (p:Person)-[r:BOARD_MEMBER_OF|OFFICER_OF]->(c)
WHERE r.source = 'irs_990'
  AND (r.uuid IS NULL OR r.created_at IS NULL OR r.weight IS NULL OR r.description IS NULL
       OR r.valid_from IS NULL OR r.title_as_filed IS NULL OR r.filing_refs IS NULL
       OR r.mention_ref IS NULL OR r.source_urls IS NULL OR r.confidence IS NULL
       OR (type(r) = 'OFFICER_OF' AND (r.role IS NULL OR NOT r.role IN ['officer','key_employee'])))
RETURN r.uuid
// OFFICER_OF target must be a nonprofit Company
MATCH (:Person)-[r:OFFICER_OF]->(c) WHERE NOT 'Company' IN labels(c) OR c.nonprofit <> true RETURN r.uuid
// School fixtures must keep their label
MATCH (c) WHERE c.ein IN ['941156365','135562308','042103580'] AND NOT 'School' IN labels(c) RETURN c.uuid
// any materialized pair edge (must never exist — pairs derive through the org node; these are not ontology edge types)
MATCH ()-[r]->() WHERE type(r) IN ['CO_BOARD_MEMBERS','CO_OFFICERS'] RETURN count(r)
```

**The delta query — the whole point of the set:**

```cypher
// per fixture org: edges by type, before vs after
MATCH (c) WHERE c.ein IN ['821433446','260017646','952210527','941156365','135562308','042103580','131684331']
OPTIONAL MATCH (c)<-[r]-()
RETURN c.ein, c.name, labels(c), type(r) AS edge, count(r) AS n ORDER BY c.ein, edge
```

Run it before (expect only `ATTENDED` / `WORKS_AT` rows, and no Ford) and after (expect `BOARD_MEMBER_OF` and `OFFICER_OF` rows on every fixture, everything that was there before unchanged).

## QA registration

Extend the `qa-the-sandbox` registry with: (1) queue quiescence = no `filing_990_org_queue` row locked longer than `ENRICHMENT_QUEUE_LOCK_TTL` **and** zero rows with `attempts >= max`; (2) mention census by `resolution_state` with the denominator printed — a run with zero mentions reports **`vacuous`**, never pass; (3) ledger vs graph parity: rows with `graph_written_at` ↔ `MATCH … r.source='irs_990'` counts; (4) the SQL queries above; (5) zero `entity.enrich_requested` events whose `source_function` is this lane; (6) the fixture-duplicate query — a second entity for any fixture EIN/domain is a **sev-1**. Real failures are counted by severity from structured logs, never by row counts.
