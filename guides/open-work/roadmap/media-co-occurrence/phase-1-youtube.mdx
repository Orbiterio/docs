## PR boundary and handoff

Suggested PR title: **Add the first media source adapter for YouTube metadata**. This PR implements the YouTube client, roster enumeration/hydration, source-specific parsing, permitted extraction and refresh/reconciliation through Phase 0's shared work/evidence interfaces. It does not reimplement shared storage, budgets, person resolution or delivery infrastructure.

[Phase 5: Facts & Graph Replay](/guides/open-work/roadmap/media-co-occurrence/phase-5-graph-replay) owns chosen claims, cache distillation, graph mutation and reader enforcement; [Phase 6: Consumer Publication](/guides/open-work/roadmap/media-co-occurrence/phase-6-publication) owns public packages. The pipeline below describes the end-to-end destination; this adapter PR stops at durable source/support state and shared reconciliation intent. It can merge with fake/fixture providers and live operations disabled. Graph/publication work can begin against those fixtures without waiting for the other source adapters.

## Provider field map and worker contract

| Official response | Normalize / persist |
| --- | --- |
| Channel `id`, `snippet.title`, `contentDetails.relatedPlaylists.uploads` | Verified roster channel key, display context and uploads playlist checkpoint/config; no default host membership |
| Playlist item `contentDetails.videoId` / `snippet.resourceId.videoId`; `nextPageToken` | Durable video child work before advancing page cursor; playlist item ID is not video identity |
| Video `id`, `snippet.title`, `description`, `channelId`, `publishedAt`, language fields | Case-preserved asset anchor, observation/snapshot and normalized scalar/extraction input; publication is not recording time |
| `contentDetails.duration`, `status`, `liveStreamingDetails` | Validated duration, availability and separate scheduled/actual timing evidence; unknown fields remain unknown |
| Search `id.videoId` and result snippet | Bounded discovery candidate only; hydrate and verify before extracting accepted evidence |

See the overview's linked [official request contracts](/guides/open-work/roadmap/media-co-occurrence#youtube-data-api-permission-gated-metadata-adapter) for endpoint parameters and quota buckets. Common returned fields are source namespace/key, observation/snapshot IDs, content revision, policy reference, coverage and a `media.extraction.v1` envelope from Phase 0. Never use the playlist insertion date as the video's publication date.

Proposed work kinds: `youtube_inventory`, `youtube_hydrate`, `youtube_search` and `youtube_reconcile`. Register them through the common dispatcher; checkpoint uploads playlist ID, pagination/overlap state and durable child IDs. A stale page token starts a bounded inventory reconciliation with item deduplication, not an unlimited restart. Search and hydration use separately accounted attempts under the actual project policy.

Synthetic handoff fixture: a video description explicitly identifies one host and one guest in a single interview; a sponsor footer names a third person. Expected adapter output is one verified appearance scope, two participant claims with validated locators and no accepted sponsor membership. A repeated source revision has the same logical evidence keys. A later corrected guest generates a new revision and targeted invalidation intent. Phase 5 tests the resulting elected facts/edges; Phase 6 tests the consumer package.

## What the adapter actually does

An approved channel or video nominates source work. Permitted metadata can supply a source anchor and candidate evidence for a canonical episode or session. One video does not automatically mean one appearance: a publisher episode can have several distribution assets, and a long video can contain several distinct sessions or interaction groups.

The shared media owner resolves appearance identity across publisher pages, RSS episodes, YouTube assets and organizer records. It creates or attaches canonical identities only after the item's scope and evidence pass the source gate. A video discussing a person is not proof that the person appeared in it.

| Layer | Responsibility |
| --- | --- |
| `entities` + `entity_identifiers` | Canonical UUIDs, verified strong aliases, candidate identifiers and merge tombstones. |
| `media_appearance` | Facts-owned typed cache for one canonical episode or session; primary key is its canonical entity ID. |
| `live_event` | Facts-owned typed cache for one organizer-defined event edition, resolved through the event owner's public interface. |
| Source and membership ledgers | Asset mappings, observations, retained snapshots, unresolved mentions, identity decisions, accepted memberships and supporting evidence. |
| `entity_facts` | Normalized scalar and relationship claims; distillation elects the claims used by typed caches and graph replay. |
| `media_work` | Durable source jobs, checkpoints, retries, leases and bounded discovery. Media jobs do not imply person/company enrichment. |
| `media_graph_receipts` | Desired/applied revisions and removal state for confirmed graph synchronization. |
| `media_outbox` | Durable delivery intent committed with the desired database change; dispatch through existing Pub/Sub and safe consumer replay. |
| Shared provider quota owner | Atomically reserves every applicable request/quota/spend bucket before provider calls; settles actual usage and retains uncertain issued attempts. |
| `publish` | Attributed, entitled consumer packages after the required revisions converge. |

## Dependencies

### Source permission comes first

Use the overview's [YouTube source contract](/guides/open-work/roadmap/media-co-occurrence#youtube-data-api-permission-gated-metadata-adapter). A valid API key proves authentication; it does not settle allowed extraction, LLM processing, aggregation, retention or redistribution. These operations stay disabled until their permitted use is established. Independently sourced publisher evidence can proceed under its own policy.

This adapter handles metadata only. Captions, transcripts, audio/video downloads, unofficial scraping, audience analytics and embeddings are outside this initial scope. Snapshot expiry must remove affected raw content and derivatives as required; an immutable snapshot is immutable only while its retention policy permits storage.

## Storage model

**Accepted decision 1: `media_appearance` and `live_event` are canonical entity types.** Their typed caches are rebuilt from chosen facts. A source adapter never authors those caches directly, stores raw provider bodies in them, or owns a second canonical ID outside `entities`.

Use the [overview's AlloyDB ledgers and applied migration record](/guides/open-work/roadmap/media-co-occurrence#alloydb-ledgers-and-transaction-boundaries):

| Shared table | YouTube responsibility |
| --- | --- |
| `media_source_roster` | Approved channel identity, source policy, adapter configuration and polling cadence. Known hosts are identity context only. |
| `media_work` | Enumeration, hydration, refresh, verification and reconciliation jobs; retain outcomes and checkpoints after completion. |
| `media_source_observations` | Every fetch outcome, including unchanged, unavailable and failed responses. |
| `media_source_snapshots` | Permitted content hash, storage key/version, parser metadata and expiry/purge state. |
| `media_appearance_sources` | Verified asset-to-appearance mappings and segment scope. |
| `media_interaction_groups` | Evidence-defined encounters within an appearance, with occurrence and completeness state. |
| `media_appearance_mentions` | Source-located names, roles and identity points, including unresolved mentions. |
| `media_resolution_attempts` | Append-only candidate, adjudication and review history. |
| `media_memberships` + `media_membership_evidence` | Accepted person/appearance memberships and independently retractable supporting claims. |
| `media_event_associations` | Verified links to an exact event edition when organizer evidence supports them. |
| `media_appearance` + `live_event` | Canonical typed caches through the facts owner. |
| `media_graph_receipts` | Revisioned graph application and retraction receipts. |
| `media_outbox` | Atomic delivery intent for work, graph and publish consumers, shared with the news workflow. |
| `provider_quota_buckets` + `provider_quota_reservations` | Shared account/project limits and per-attempt reservations; separate search calls, endpoint units and applicable spend ceilings. |

News ledgers remain owned by the overview's separate closed-world news phase. The existing Fundable tables remain in Universe and are not recreated for media.

The old names `media_video_queue`, `media_appearance_mention`, `media_resolution_attempt` and `media_appearance_edge` are not additional parallel stores. Their required responsibilities are represented by the shared tables above. The old `media_youtube_quota` DDL is replaced by the two accepted shared quota tables; it is not an additional table. Quota reservation remains required before live calls.

### Appearance identity and aliases

Resolve a known source through verified aliases and the shared owner before admitting a new appearance. Strong aliases require exact item scope: case-sensitive YouTube video IDs, feed-scoped exact RSS GUIDs, verified publisher episode URLs and organizer/edition/session identifiers. A multi-session video is an asset mapping with explicit segment scope, not a globally unique appearance alias for every session in it.

Titles, dates, channel names, handles and a host's name are candidate evidence. They do not silently merge episodes, clips or editions. Preserve historical aliases after a reviewed merge and repoint memberships, claims and pending work through canonical IDs.

Graph node identity follows the canonical entity owner. Do not restore the old lowercased `youtube::<video_id>` appearance key. Exact key normalization, uniqueness and graph upsert contracts are Phase 0 review items; accepting canonical entities is not approval of an unreviewed key algorithm.

### Graph contracts

Use [Node Types](/guides/ontology/nodes#media-appearances), [Edge Types](/guides/ontology/edges#media-edges) and the overview's [facts and replay contract](/guides/open-work/roadmap/media-co-occurrence#facts-graph-contract-and-correction-replay).

Only chosen relationship facts authorize `APPEARED_IN` and, where verified, `SESSION_OF`. Membership and source ledgers hold the supporting evidence; receipts track whether the elected revision reached the graph. New evidence, role corrections, expiry and retractions must change desired state and replay. A first-write timestamp alone cannot represent that state.

Preserve explicit roles and interaction scope: host/guest use 15; panelist/moderator use 20; a verified speaker follows the overview's event-size rule. Do not infer a panel from participant count or infer that everyone in one video encountered everyone else. Required edge properties include `description` and `description_generated_at`, alongside identity, provenance, occurrence, policy and revision fields in the master schema.

Graph node and edge writes remain under the shared graph gate. Reader enforcement and source permission are prerequisites for publication or scoring. The old rule that nodes write regardless of the gate is withdrawn.

## Pipeline

1. **Admit bounded source work.** Resolve an approved roster/source policy and durable request key. Use `media_work` with its own claim/lease contract and the overview's admitted priorities. An appearance's entity type does not route it into the generic company dispatcher.
2. **Reserve, enumerate and hydrate.** Reserve all applicable capacity through the shared budget owner before each request attempt, including retries. Use channel content details to find the uploads playlist, persist each enumeration page before advancing, and hydrate bounded batches through `videos.list`. Settle known usage and retain uncertain issued reservations for reconciliation. Asset IDs retain case. Classify unavailable, upcoming and failed items separately.
3. **Persist permitted evidence.** Store an observation and a policy-bounded snapshot pointer before parsing. Reconcile uploaded objects after partial failures. An unchanged response does not erase prior evidence; a changed source yields a new revision.
4. **Extract source-located mentions.** Treat provider text as untrusted data. Require locatable participant evidence and preserve ambiguous or unknown roles. A roster host is not an automatic participant; a topic subject, sponsor or description footer is not an appearance.
5. **Resolve identity and item scope.** Strong identifiers and reviewed matches can resolve a person; prior appearances, channel history and employer/title similarities nominate candidates. Each occurrence still needs its own evidence. Record negative and inconclusive decisions. Do not create a person from a bare name.
6. **Resolve canonical appearances and groups.** Attach verified source anchors to an existing entity or admit a new canonical identity through the shared owner. Keep disjoint sessions and clips distinguishable. Create memberships only for accepted participant/occurrence claims.
7. **Normalize, elect and replay.** Submit normalized claims through the facts owner. Typed caches come from chosen facts. Persist desired state and `media_outbox` intent atomically under the [accepted outbox contract](/guides/open-work/roadmap/media-co-occurrence#transactional-outbox-accepted-decision-2). Broker acceptance stamps dispatch only; graph receipts and publish readiness establish consumer completion.
8. **Refresh and repair.** Revisit an overlap and reconcile inventory. Do not stop permanently at the first previously seen video or interpret a truncated feed/playlist as deletion. Expiry, retraction and receipt repair continue when new fetching is paused.

New-person admission defaults off. If separately enabled, it uses the overview's validated identity, cap and bounded-leaf rules. Source work never implicitly dispatches recursive person or company enrichment.

## Package layout

Follow the overview's owner: orchestration under proposed `internal/features/enrichment/media`, parent enrichment adapters for SQL and public dependencies, a YouTube client under `internal/clients`, facts-owned mappings/distillation, graph synchronization and publish-owned projection. Wire narrow public interfaces in `internal/app`.

The earlier separate `internal/features/media` ownership and competing `mediapub.AppearanceWriter` are withdrawn. Publisher, Deep Bio and organizer candidates enter the same media identity/evidence gate through the chosen public owner interface. Deep Bio show-level URLs do not bypass episode verification.

## Smoke tests

Expected counts come from labeled fixtures, not assumptions about the number of videos or the popularity of a channel.

| Case | Required assertion |
| --- | --- |
| RSS episode, publisher page and verified YouTube distribution of the same item | One canonical appearance, multiple independently traceable source anchors and no duplicate membership. |
| Same title/date on two different episodes | Separate canonical appearances unless stronger verified evidence proves equivalence. |
| One video containing two disjoint sessions | Explicit appearance/group scope; no cross-session pair eligibility. |
| Case-distinct YouTube IDs or RSS GUIDs | Remain distinct through lookup, storage and replay. |
| Known host absent from episode evidence | No default host membership. |
| Several guests with no panel evidence | No automatic panel classification. |
| Topic subject or sponsor mention | No accepted appearance membership from that mention alone. |
| Same name on a prior episode, conflicting current identity evidence | No inherited automatic match; preserve the conflict for resolution. |
| New person disallowed, but the appearance is verified | Preserve unresolved/reviewable mention evidence without creating a person. |
| Duplicate work delivery or repeated snapshot revision | No duplicate accepted claim, membership, logical delivery intent or graph relationship. |
| Role correction, source expiry, or one of several sources withdrawn | Re-elect affected claims and apply only the current desired revision; surviving permitted evidence remains usable. |
| Graph gate closed | No graph node or edge writes. |
| Provider budget exhausted | Defer before the call; release source work without consuming a failure attempt. All applicable bucket reservations succeed atomically or none does. |
| Request times out, its worker lease expires, or the quota window resets | Retain uncertain issued usage; reconcile once against the charged window. A retry needs its own accounted attempt; a reset or key rotation does not erase unsettled usage. |
| Publisher evidence survives removal of a YouTube source | Canonical appearance and independently supported claims survive; affected YouTube content and derivatives follow their deletion policy. |

Schema integration tests now cover subtype identity, source/membership dedup, retained evidence, frozen-index consistency, ordered article pairs, quota lifecycle constraints and outbox/revision uniqueness. Transaction races, stale-worker behavior and consumer replay still need their future Go implementations and tests. Graph assertions must use the finalized canonical identity and revision contract. The previous queries against withdrawn table names are not acceptance tests for this model.
