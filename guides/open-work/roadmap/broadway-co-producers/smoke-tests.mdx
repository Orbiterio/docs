**Status: all runs below were executed against the local stack (Postgres 5434, FalkorDB `orbiter-falkordb`, API on 8090, worker on 8091) while the lane was built.** Each smoke names the entry point it drives so the same run can be repeated against dev once the migrations land. Decision ids (`D31`, `D55`) point at the `stage-enrichment` skill's log in `orbiter-universe`, where the full outcome and every fix each smoke forced are recorded.

<Info>
**Conventions used in every call.** Staff routes take `Authorization: Bearer staff` on the local API (`STAFF_TOKENS` in `.env`). The consumer get-add takes the smoke client key: `Authorization: Bearer $(cat .smoke-key)`. Worker events are delivered by hand with a Pub/Sub push to `localhost:8091/pubsub/push`, the body's `data` being the base64 JSON payload and `attributes.event_type` the event name. Restart **both** the API and the worker after a code change; a stale worker silently skips a claim the API just made. Feature flags the smokes needed on: `STAGE_ENABLED`, `STAGE_RESOLUTION_ENABLED`, `STAGE_DISCOVERY_ENABLED`, `STAGE_EDGE_WRITES_ENABLED`, `STAGE_PUBLISH_ENABLED`, `STAGE_LLM_ENABLED`, `STAGE_ADAPTATION_ENABLED`, `STAGE_MUSIC_DISCOVERY_ENABLED`, plus `ENRICHMENT_MUSIC_QUEUE_DRAIN_ENABLED=true` for the music seeds and `GCS_MODE=gcp` with `GCS_BUCKET=orbiter-sandbox` for the cover drain.
</Info>

## Entry points

The lane has five doors in and one tick per phase. Every smoke below is filed under the door it walked through.

| Entry point | Route or event | Handler |
| --- | --- | --- |
| Pilot submission (a hand-built roster) | `POST /v1/admin/enrichment/stage/submissions` | `submitStageProduction` |
| Direct admission by registry id | `POST /v1/admin/enrichment/stage/productions` | `admitStageProduction` → `stage.Admit` |
| Theatre person trigger | `POST /v1/enrichment/persons/get-add` → person run → `stepStageDiscovery` → `POST /v1/admin/enrichment/stage/discovery` | `DiscoverStageRootsOnce` |
| Derived works (BASED_ON) | `POST /v1/admin/enrichment/stage/adaptations` or event `enrichment.stage_adaptations_requested` | `RunStageAdaptationsOnce` |
| Music → stage (cast recordings) | `POST /v1/admin/enrichment/music/seed` → queue drain → `POST /v1/admin/enrichment/stage/music` or event `enrichment.stage_music_requested` | `DiscoverMusicStageOnce` |
| Phase ticks | `POST /v1/admin/enrichment/stage/{drain,resolve,facts,graph,publish}` | one obligation phase each |
| Review door | `POST /v1/admin/enrichment/stage/mentions/{id}/review`, `POST /v1/admin/entities/reviews/{id}/merge` | reviewer accept / reject / revoke, human merge |
| Inspection | `GET /v1/admin/enrichment/stage/productions/{id}`, `GET /v1/admin/enrichment/stage/mentions?production_id=…`, `GET /v1/entities/{id}/projection` | status, mention queue, the published package |

The phase ticks are the same for every smoke, so they are listed once:

```bash
H='Authorization: Bearer staff'; C='Content-Type: application/json'
for p in drain resolve facts graph publish; do
  echo "--- $p"
  curl -s -m 600 -X POST localhost:8090/v1/admin/enrichment/stage/$p -H "$H" -H "$C" -d '{"max_productions":10}'
done
```

`drain` takes `{"max_rows":N}` or `{"queue_id":"<stage_source_job id>"}` instead of `max_productions`. A pass that stops on the search budget answers `continued`; run it again.

## 1. Pilot submission: Rent (2026-09-07)

**Entry point:** `POST /v1/admin/enrichment/stage/submissions`. The fixture is `.local/rent-submission.json` in the repo checkout (git-excluded): a hand-built roster of the 1996 Broadway production from IBDB billing, `registry_id: broadway:rent-1996`.

```bash
H='Authorization: Bearer staff'
curl -s -w '\nHTTP %{http_code}\n' -X POST localhost:8090/v1/admin/enrichment/stage/submissions \
  -H "$H" -H 'Content-Type: application/json' --data-binary @.local/rent-submission.json

P=01a07e83-6194-7a9a-9532-35623670a0f6   # the production the admission answered
curl -s -X POST localhost:8090/v1/admin/enrichment/stage/drain   -H "$H" -H 'Content-Type: application/json' -d '{"max_rows":5}'
curl -s -X POST localhost:8090/v1/admin/enrichment/stage/resolve -H "$H" -H 'Content-Type: application/json' -d '{"max_productions":5}'
curl -s "localhost:8090/v1/admin/enrichment/stage/mentions?production_id=$P" -H "$H"
```

Mentions the ladder could not settle were accepted through the review door, one call per mention:

```bash
curl -s -X POST "localhost:8090/v1/admin/enrichment/stage/mentions/$MENTION/review" -H "$H" -H 'Content-Type: application/json' \
  -d '{"decision":"accept","entity_id":"'"$ENTITY"'","expected_identity_revision":1,"reason":"IBDB original Broadway production billing; local smoke test"}'
```

Then `facts`, `graph`, and the retraction test:

```bash
curl -s -X POST localhost:8090/v1/admin/enrichment/stage/mentions/01a07e83-7ba8-7cec-9f28-c7623a91b69f/review -H "$H" -H 'Content-Type: application/json' \
  -d '{"decision":"revoke","expected_identity_revision":2,"reason":"smoke test: prove the retraction"}'
curl -s -X POST localhost:8090/v1/admin/enrichment/stage/graph -H "$H" -H 'Content-Type: application/json' -d '{"max_productions":5}'
```

**Proved:** submission → drain → resolve → review → facts → graph end to end; seven accepted producers, seven `PRODUCED` edges; the revoke flips the edge inactive. **Forced:** D31 (a withdrawn link re-raises the facts obligation, not only an accept). A forced re-run of the unchanged submission re-raises resolve and facts (verified again on 2026-09-08 under D45).
