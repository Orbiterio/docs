## Start here

**Contacts View** is a new full-screen route, `/contacts`, reached from the ⌘K palette next to **Activity View** and **Network View**. It renders every contact the signed-in user owns as a row in a virtualized TanStack Table, lets the user add typed custom columns, save named views, and drives the whole table from the same query composer that sits at the bottom of Discover and Collections. The composer is not a chat surface: it is an LLM call with tools whose only job is to change the table (filter, sort, group, columns, fields, values) or hand the current rows to an existing feature (collections, outreach).

| Repository / runtime | Owns |
| --- | --- |
| `orbiter-backend` — Go | `GET /v1/contacts/table` row projection, custom-field definitions and values, saved views, query log. All database access. |
| `orbiter-frontend` — TanStack Start server, TypeScript | `POST /api/contacts-view-query`: the `chat()` loop, system prompt, tool definitions, streaming, query-log write. No Go, no business writes. |
| `orbiter-frontend` — browser, React | `/contacts` route, `contacts-view` feature, TanStack Table v9 + TanStack Virtual, client tools that mutate table state and call Go with the user's own session, confirm cards, person sheet reuse. |

Go runs only in orbiter-backend. The LLM loop runs only in the TanStack Start server. Every write to Go is made from the browser with the user's session, exactly like every other feature; the BFF never holds a privileged credential.

## Decisions

Each answer was chosen from options with a stated recommendation; the recommended option was taken in every case except 4 and 10, where more scope was selected.

| # | Question | Decision | Why |
| --- | --- | --- | --- |
| 1 | Which endpoint feeds the rows? | **New Go endpoint `GET /v1/contacts/table`.** | The frontend already reads Go `GET /v1/contacts` on `dev` (`src/features/contacts`), but that list item is shared by search and widgets and stays narrow. The table needs a wider, flatter projection plus custom-field values. |
| 2 | Where do filter/sort/group run? | **Client-side full dataset, virtualized.** | Hydrate all rows once; TanStack Table does the work in the browser; TanStack Virtual keeps the DOM small. AI tools become pure state deltas instead of API calls. Comfortable to roughly 20k rows. |
| 3 | Custom-field storage | **`persons.contact_field_defs` + a `custom_fields` JSONB column on `persons.contacts`, GIN-indexed.** | AlloyDB is Postgres, so JSONB and GIN are available (the archived Deal Flow typed-EAV design existed only because Xano has no GIN). Adding a field is a row insert, not a migration. |
| 4 | What may the AI tools do? | **All four tiers:** view state; create field definitions; bulk-set values on matching rows; hand rows to collections and outreach. | Writes are gated by decision 11. |
| 5 | Where does the LLM loop run? | **TanStack Start server with `@tanstack/ai` tools.** | The Go OpenRouter client (`internal/clients/openrouter`) supports `response_format` structured output only: no `tools`, no streaming. The TanStack AI BFF already has tool calling, and `@tanstack/ai` 0.38 (installed) has `.client()`, `needsApproval`, and `createChatClientOptions`. |
| 6 | Conversation state | **Multi-turn, in memory per view session.** | Each turn carries the last turns plus a compact table snapshot, so "now also sort by last activity" works. Nothing persisted; Go logs each query for telemetry only. |
| 7 | Saved views | **Named views in Go + `?view=` URL param + localStorage last-state.** | `persons.contact_views` with a versioned state JSON. |
| 8 | Custom-field ownership | **Per user in v1, `scope_type` + `scope_id` in the schema for org-shared later.** | No migration when org sharing arrives. |
| 9 | Which contacts are rows? | **My contacts only.** | `user_id = caller` and `merged_into_contact_id IS NULL`, the same predicates as `ListContactsByUser`. |
| 10 | Row interaction | **Name opens the existing PersonSheet; inline edit for custom cells, note and nickname; row checkboxes feed the global node-selection store.** | Reuses `PersonSheet` (mounted in `_authed.tsx`, driven by the `person` search param) and `useNodeSelectionStore`, so Email Outreach Composer and add-to-collection work unchanged. |
| 11 | Bulk write policy | **Always preview and confirm.** Field creation is the one exception: additive, applied immediately, undone by delete. | Every many-row or cross-feature write shows affected count, sample rows and the exact change; nothing writes without the Apply click. |
| 12 | Rollout | **`VITE_CONTACTS_VIEW` flag hides the palette command and redirects the route.** | Same shape as the `VITE_TANSTACK_AI_CHAT_*` flags. Ships dark, enabled per environment. |

### Assumed defaults

Chosen by the author; override in place without reopening the workshop.

- **Route** `/contacts`. Palette command id `contacts-view`, label "Contacts View", category Navigation, lucide `TableIcon`. No hotkey in v1.
- **Default columns, in order:** select, Name (pinned start), Title, Company, Location, Email, Last activity, Kind, Momentum, Emails, Meetings, Connected, Note, Nickname, Added. Custom columns append after Added in `position` order.
- **Row cap** 25,000 with a banner ("showing the first 25,000 of N; narrow with search"); page size 1,000 per request; compact 40 px rows.
- **Custom field types in v1:** `text`, `number`, `date`, `checkbox`, `select`, `multi_select`, `url`. `person_ref` and `company_ref` wait for a picker (see Later).
- **Model:** `CONTACTS_VIEW_QUERY_MODEL` server env, defaulting to the chat BFF default `anthropic/claude-sonnet-4.5` via OpenRouter, provider sort `throughput`. Bake off cheaper tool-callers after Phase 5.
- **Conversation memory:** last 10 user/assistant pairs, reset when the route unmounts. `describe_table` tool outputs are dropped from history after the turn they served.
- **Query log:** fire-and-forget `POST /v1/contacts/table/query-log` from the BFF after each turn, using the user's bearer.
- **Export CSV:** out of v1.

## Navigation and palette command

### How existing navigation commands work

All palette commands are one array in `src/features/command-palette/constants/commands.tsx`, returned by `getCommands(navigate, queryClient, currentUser)`. Each entry is a `CommandDefinition` with `id`, `label`, `category` (`"Navigation" | "Actions" | "Tools"`), `icon`, `action`, and optional `hidden`, `shortcut` (display string) and `hotkey` (a `react-hotkeys-hook` combo). Three consumers read that array and need no changes:

- `command-palette.tsx` filters `category === "Navigation" && !hidden` into the **Navigation** group and calls `cmd.action()` on select.
- `hooks/use-command-hotkeys.ts` binds every command's `hotkey` with `useHotkeys`, enabled only when `hotkey` is set and the command is not hidden.
- `_authed.tsx` mounts the palette and `useCommandPaletteShortcut()` (⌘K) once for every protected route.

The three existing navigation commands navigate with `navigate({ to: "/" })` (Activity View), `navigate({ to: "/network" })` (Network View) and `navigate({ to: "/email-inbox" })` (Email Inbox). `navigate` is typed against `src/routeTree.gen.ts`, so the route file must exist before the command compiles.

### Steps for the AI agent

1. **Add the feature flag** in `src/env.ts`. In the client schema block add `VITE_CONTACTS_VIEW: tanstackAiChatFlagSchema` (the existing schema that parses the string `"true"` to a boolean) and in the `runtimeEnv` block add `VITE_CONTACTS_VIEW: import.meta.env.VITE_CONTACTS_VIEW`. In the server block add `CONTACTS_VIEW_QUERY_MODEL: z.string().min(1).optional()` with its `process.env` mirror. Add both keys to `.env.example` and the Netlify environment for staging.

2. **Create the route file** `src/routes/_authed/contacts.tsx` (skeleton below). Run `pnpm dev` once so the router plugin regenerates `src/routeTree.gen.ts`; never edit that file by hand.

3. **Add the command** to `commands.tsx`, directly after the `network-view` entry so it sits between Network View and Email Inbox in the Navigation group:

```tsx src/features/command-palette/constants/commands.tsx
// 1. extend the lucide import list at the top of the file
import { TableIcon } from "lucide-react";
// 2. read the flag
import { env } from "@/env";

// 3. inside getCommands(...) — after the "network-view" entry
{
  id: "contacts-view",
  label: "Contacts View",
  category: "Navigation",
  icon: <TableIcon className="size-4" />,
  action: () => navigate({ to: "/contacts" }),
  hidden: !env.VITE_CONTACTS_VIEW,
},
```

4. **Verify** with the browser: open ⌘K, type "cont", confirm "Contacts View" appears under Navigation only when `VITE_CONTACTS_VIEW=true`, press Enter, confirm the URL is `/contacts` and the table renders. With the flag off, confirm the command is absent and a direct visit to `/contacts` redirects to `/`.

5. **Do not** add a TopNav tab or an `ActiveView` entry. Contacts View is a route like Email Inbox, not an active view inside `/network`.

A hotkey is intentionally left off in v1. To add one later, set `shortcut: "⌥⇧V"` and `hotkey: "alt+shift+v"` on the same entry; `useCommandHotkeys` picks it up with no other change.

### Route skeleton

```tsx src/routes/_authed/contacts.tsx
import { createFileRoute, redirect } from "@tanstack/react-router";
import { DefaultNotFound } from "@/components/global/default-not-found";
import Loader from "@/components/global/loader";
import { env } from "@/env";
import { contactFieldDefsQueryOptions } from "@/features/contacts-view/api/use-contact-field-defs";
import { contactViewsQueryOptions } from "@/features/contacts-view/api/use-contact-views";
import { contactsTableRowsQueryOptions } from "@/features/contacts-view/api/use-contacts-table-rows";
import { ContactsViewPage } from "@/features/contacts-view/components/contacts-view-page";

// `person` and `active-tab` must survive validation: PersonSheet is mounted
// in _authed.tsx and reads them from useSearch on every route.
type ContactsSearchParams = {
  view?: string;
  q?: string;
  person?: string;
  "active-tab"?: string;
};

const str = (v: unknown) => (typeof v === "string" && v ? v : undefined);

export const Route = createFileRoute("/_authed/contacts")({
  beforeLoad: () => {
    if (!env.VITE_CONTACTS_VIEW) throw redirect({ to: "/" });
  },
  validateSearch: (search: Record<string, unknown>): ContactsSearchParams => ({
    view: str(search.view),
    q: str(search.q),
    person: str(search.person),
    "active-tab": str(search["active-tab"]),
  }),
  loader: async ({ context: { queryClient } }) => {
    // Warm defs, views and the first rows page. Errors never block navigation.
    await Promise.allSettled([
      queryClient.ensureQueryData(contactFieldDefsQueryOptions()),
      queryClient.ensureQueryData(contactViewsQueryOptions()),
      queryClient.ensureInfiniteQueryData(contactsTableRowsQueryOptions()),
    ]);
  },
  staleTime: 60 * 1000,
  component: ContactsViewPage,
  pendingComponent: () => <Loader />,
  notFoundComponent: DefaultNotFound,
});
```

`ContactsViewPage` renders the global `Header` from `src/components/global/header.tsx` above the table, the same way `EmailInboxPage` does.

## Rows endpoint

### Contract

`GET /v1/contacts/table` — the caller's live contacts as flat table rows, keyset-paged in large pages for full hydration. Lives in the `persons` feature next to `GET /v1/contacts` and is registered inside the existing `r.Route("/contacts", …)` block in `internal/features/persons/handler.go` as `r.Get("/table", …)`. Auth is the module-level `RequireWorkOS`; the owner is `pmw.OrbiterUserID(r)`, never a body or query field.

| Query param | Type | Notes |
| --- | --- | --- |
| `limit` | int | Default 500, max 1,000. Above `pagination.MaxLimit`, so the handler uses its own bound, not `Page.Normalize()`. |
| `cursor` | string | Opaque keyset cursor on `(created_at DESC, id DESC)`. Empty on the first call. |

There is no `sort` or `query` param: order is fixed for a stable keyset and every sort and filter happens in the browser (decision 2).

Success envelope is the standard `{data, error, meta}` via `pmw.OKMeta`, with `data` an array of rows and `meta` carrying `total`, `nextCursor` (empty string on the last page) and `fieldDefsVersion` (max `updated_at` of the caller's field definitions, so the client can detect drift).

```sql internal/features/persons/queries/listings.sql — new query
-- name: ListContactTableRowsByUser :many
-- Flat row projection for Contacts View. Fixed keyset on (created_at DESC, id DESC);
-- all sorting/filtering is client-side. Excludes merged-away tombstones.
SELECT
    c.id                        AS contact_id,
    c.person_id,
    c.created_at,
    c.updated_at,
    TRIM(CONCAT_WS(' ', mp.first_name, mp.middle_name, mp.last_name)) AS name,
    mp.first_name,
    mp.last_name,
    c.nickname,
    mp.avatar,
    EXISTS (SELECT 1 FROM users.users u WHERE u.person_id = mp.id) AS orbiter_user,
    mp.current_title,
    mc.id                       AS company_id,
    mc.name                     AS company_name,
    mc.logo                     AS company_logo,
    ploc.id                     AS location_id,
    ploc.formatted_location     AS location_formatted,
    pe.email_address            AS primary_email,
    COALESCE(ec.email_count, 0)::int AS email_count,
    c.connected_at,
    c.last_activity_at,
    c.last_activity_kind,
    c.last_email_activity_id,
    c.last_calendar_event_id,
    c.total_email_activity,
    c.total_remote_events,
    il.total_emails,
    il.total_meetings,
    il.momentum,
    c.note,
    c.visibility,
    c.custom_fields
FROM persons.contacts c
JOIN persons.persons mp ON mp.id = c.person_id
LEFT JOIN companies.companies mc ON mc.id = mp.current_company_id
LEFT JOIN locations.primary_locations ploc ON ploc.id = mp.primary_location_id
LEFT JOIN persons.contacts_interaction_log il ON il.contact_id = c.id
LEFT JOIN LATERAL (
    -- first email by creation; reuse the exact tables ListUserContactEmails joins
    SELECT ea.email_address
    FROM persons.contact_emails ce
    JOIN emailaddresses.email_addresses ea ON ea.id = ce.email_address_id
    WHERE ce.contact_id = c.id
    ORDER BY ce.created_at ASC
    LIMIT 1
) pe ON TRUE
LEFT JOIN LATERAL (
    SELECT COUNT(*) AS email_count
    FROM persons.contact_emails ce
    WHERE ce.contact_id = c.id
) ec ON TRUE
WHERE c.user_id = sqlc.arg(user_id)
  AND c.merged_into_contact_id IS NULL
  AND (c.created_at, c.id) < (
        COALESCE(sqlc.narg(cursor_time)::timestamptz, 'infinity'::timestamptz),
        COALESCE(sqlc.narg(cursor_id)::uuid, 'ffffffff-ffff-ffff-ffff-ffffffffffff'::uuid))
ORDER BY c.created_at DESC, c.id DESC
LIMIT sqlc.arg(row_limit);
```

<Note>
Confirm the two email table names against `ListUserContactEmails` in `queries/contacts.sql` before generating; the lateral joins above name them from the `ContactEmail` wire shape (`contact_id`, `email_address_id`) and must match the real schema. The `'infinity'` sentinel replaces the `NOW()` default used by `ListContactsByUser` so a contact created between two page requests is not skipped. Run `make sqlc-generate` after editing.
</Note>

## Custom fields

### Schema

Migration `migrations/{ts}_persons_021_contact_custom_fields.sql`. The `persons` feature is at `020`, so this is `021`; re-timestamp to "now" right before merge (see `migrations/CLAUDE.md`).

```sql persons_021_contact_custom_fields.sql
-- +goose Up
-- User-defined contact columns. Definitions are schema-as-data; values live in a
-- JSONB column on persons.contacts keyed by definition id. scope_type/scope_id
-- exist so org-shared definitions can arrive without a migration; v1 writes
-- scope_type='user' only. Enums (scope_type, field_type) are Go validators,
-- not CHECKs, per repo policy.
CREATE TABLE persons.contact_field_defs (
    id            UUID        PRIMARY KEY,
    scope_type    TEXT        NOT NULL,              -- 'user' | 'org'
    scope_id      UUID        NOT NULL,              -- users.users.id for 'user'
    key           TEXT        NOT NULL,              -- slug, immutable after create
    label         TEXT        NOT NULL,
    field_type    TEXT        NOT NULL,              -- text|number|date|checkbox|select|multi_select|url
    options       JSONB       NOT NULL DEFAULT '[]'::jsonb,  -- [{id,label,color}] for select types
    config        JSONB       NOT NULL DEFAULT '{}'::jsonb,  -- per-type settings (number.precision, …)
    position      INTEGER     NOT NULL DEFAULT 0,
    archived_at   TIMESTAMPTZ,
    created_by_id UUID        NOT NULL REFERENCES users.users(id) ON DELETE CASCADE,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX contact_field_defs_scope_key_uniq
    ON persons.contact_field_defs (scope_type, scope_id, key);
CREATE INDEX contact_field_defs_scope_position_idx
    ON persons.contact_field_defs (scope_type, scope_id, position);

ALTER TABLE persons.contacts
    ADD COLUMN custom_fields JSONB NOT NULL DEFAULT '{}'::jsonb;

-- jsonb_path_ops: smaller index, supports @> containment which is all the
-- server-side "has value X" checks need. Client does the rest.
CREATE INDEX contacts_custom_fields_gin
    ON persons.contacts USING GIN (custom_fields jsonb_path_ops);

-- +goose Down
DROP INDEX IF EXISTS persons.contacts_custom_fields_gin;
ALTER TABLE persons.contacts DROP COLUMN IF EXISTS custom_fields;
DROP INDEX IF EXISTS persons.contact_field_defs_scope_position_idx;
DROP INDEX IF EXISTS persons.contact_field_defs_scope_key_uniq;
DROP TABLE IF EXISTS persons.contact_field_defs;
```

`scope_id` has no foreign key because it is polymorphic; the service enforces `scope_type='user' AND scope_id = caller` on every write in v1.

### Value shapes

Values are keyed by definition **id** (stable, never renamed), not by `key`.

| `field_type` | JSON value | Validation |
| --- | --- | --- |
| `text` | string | max 2,000 chars, trimmed |
| `number` | number | finite; `config.precision` 0–4 |
| `date` | `"YYYY-MM-DD"` string | valid calendar date |
| `checkbox` | boolean | — |
| `select` | option id string | must be a live option id on the definition |
| `multi_select` | array of option id strings | each a live option id, max 25, deduplicated |
| `url` | string | parses as `http` or `https` |

Clearing a value removes the key: `custom_fields = custom_fields - $key`. Setting merges: `custom_fields = custom_fields || jsonb_build_object($key, $value)`.

### Endpoints

All under the `persons` feature, inside the `/contacts` route group, owner-scoped by `pmw.OrbiterUserID`.

| Operation ID | Method and path | Purpose |
| --- | --- | --- |
| `listContactFieldDefs` | `GET /v1/contacts/fields` | Caller's definitions, unarchived first, by `position`. Includes archived with `?include_archived=true`. |
| `createContactFieldDef` | `POST /v1/contacts/fields` | Body `label`, `field_type`, optional `options`, `config`. `key` is slugified from `label` with a numeric suffix on collision. Max 50 live definitions per scope. |

### Table setup

```ts src/features/contacts-view/lib/table-features.ts

  aggregationFn_count, aggregationFn_sum, aggregationFn_uniqueCount,
  columnFacetingFeature, columnFilteringFeature, columnGroupingFeature,
  columnOrderingFeature, columnPinningFeature, columnResizingFeature,
  columnSizingFeature, columnVisibilityFeature, globalFilteringFeature,
  createExpandedRowModel, createFacetedRowModel, createFacetedUniqueValues,
  createFilteredRowModel, createGroupedRowModel, createSortedRowModel,
  filterFn_includesString, metaHelper, rowAggregationFeature,
  rowExpandingFeature, rowSelectionFeature, rowSortingFeature,
  sortFn_alphanumeric, sortFn_text, tableFeatures,
} from "@tanstack/react-table";
import { contactFilterFns } from "./filters";       // op-based filterFn built on the row value + type
import type { ContactsColumnMeta, ContactsTableMeta } from "./columns";

export const contactsTableFeatures = tableFeatures({
  rowSortingFeature, columnFilteringFeature, columnFacetingFeature, globalFilteringFeature,
  columnGroupingFeature, rowAggregationFeature, rowExpandingFeature,
  columnVisibilityFeature, columnOrderingFeature, columnPinningFeature,
  columnSizingFeature, columnResizingFeature, rowSelectionFeature,

  facetedUniqueValues: createFacetedUniqueValues(),
  sortFns: { alphanumeric: sortFn_alphanumeric, text: sortFn_text },
  filterFns: { includesString: filterFn_includesString, contactOp: contactFilterFns.contactOp },
  aggregationFns: { count: aggregationFn_count, sum: aggregationFn_sum, uniqueCount: aggregationFn_uniqueCount },
  tableMeta: metaHelper<ContactsTableMeta>(),
  columnMeta: metaHelper<ContactsColumnMeta>(),
});
export type ContactsTableFeatures = typeof contactsTableFeatures;
```

- **Columns** come from `createColumnHelper<ContactsTableFeatures, ContactTableRow>()`. Core columns are static; custom columns are generated from field definitions with `id: "cf_" + def.id`, `accessorFn: row => row.custom_fields[def.id] ?? null`, `meta: { fieldDef }`, `filterFn: "contactOp"`, a type-aware `sortFn`, and `aggregationFn` `uniqueCount`. Rebuild the column array with `useMemo` on the defs query.
- **Row id** is `getRowId: row => row.contact_id`, so selection and edits survive re-sorts.
- **One filter function, many ops.** `contactOp` reads a filter value of shape `{ op, value }` (ops: `includes`, `equals`, `in`, `not_in`, `gt`, `gte`, `lt`, `lte`, `between`, `before`, `after`, `is_empty`, `not_empty`) and dispatches on the column's `meta.type`. This keeps the AI tool schema and the UI chips identical and avoids registering a dozen built-ins.
- **State** lives in one zustand store (`use-contacts-view-state.ts`) holding `ContactsViewState` plus an undo stack, passed to `useTable` as `state` with matching `on*Change` handlers. One writer means the UI, the URL, localStorage, saved views and the AI client tools all mutate the same object. Use the `useTable` selector argument to subscribe only to what each component reads, and `table.Subscribe` around the body.
- **Virtualization**: `useVirtualizer({ count: rows.length, getScrollElement: () => scrollRef.current, estimateSize: () => 40, overscan: 12, getItemKey: i => rows[i].id })` over `table.getRowModel().rows`. Grid-display `table` with a sticky `thead`, `tbody` at `getTotalSize()` height, rows absolutely positioned with `translateY(virtualRow.start)`. Fixed row height; no `measureElement`. Column virtualization is not needed under 40 columns.
- **Editing**: `tableMeta.updateCell(contactId, columnId, value)`; custom cells, Note and Nickname are editable (Enter or F2 to edit, Esc to cancel, Tab commits and moves right). Edits are optimistic via `queryClient.setQueryData` on the rows query, then `PATCH /v1/contacts/{id}/fields`, `PATCH /v1/contacts/{id}/note`, or the nickname endpoint. Core person columns are read-only.
- **Selection**: `rowSelection` → effect in `use-sync-row-selection.ts` writes `SelectedNode { id: person_id, type: "person", name, imageUrl: avatar }` entries into `useNodeSelectionStore` under mode `"contacts-view"`, so **Email Outreach Composer** (`useSelectedNodes`) and add-to-collection work unchanged.
- **Person sheet**: clicking a name runs `navigate({ search: prev => ({ ...prev, person: row.person_id }) })`; `PersonSheet` in `_authed.tsx` opens from the `person` param.
- **Faceting** (`getFacetedUniqueValues`) powers both the filter chips' value pickers and the snapshot the model receives.

### Tools

All tools are defined once in `tools/definitions.ts` with `toolDefinition({ name, description, inputSchema, outputSchema, needsApproval? })` and implemented in `tools/client-tools.ts` with `.client((input, ctx) => …)`, where `ctx` carries the store, the table instance, the query client and the mutations. The browser holds the dataset, so target resolution (which rows a filter matches) can only happen there; that is why there are no server tools.


### Conversation handling

`useChat` keeps the transcript in component state. Before each send, the client trims to the last 10 pairs and strips `describe_table` tool outputs older than the current turn. Leaving the route unmounts the hook and forgets the transcript. Nothing is written to `/v1/copilot` threads; the copilot harness-signature rules from the outcome chat plan do not apply because no server-authored history exists.

1. Palette lists "Contacts View" under Navigation only when `VITE_CONTACTS_VIEW=true`; Enter navigates to `/contacts`; with the flag off `/contacts` redirects to `/`.
2. A user with 8,410 contacts sees all rows after hydration; the toolbar count matches `meta.total`; a second user's contacts never appear.
3. A contact merged into another (tombstoned) does not appear.
4. Scrolling 20,000 rows keeps under 200 DOM rows at any time.
5. Sorting by Company, filtering Company in [Acme], grouping by Location, hiding Note and pinning Name all round-trip through a saved view and the URL.
6. Each custom-field type accepts a valid value and rejects an invalid one with a field-level error; clearing removes the key from JSONB.
7. Deleting a field removes its column, its values on every contact of the user, and any saved-view reference.
8. Row checkboxes select nodes visible to Email Outreach Composer; clearing selection clears them.
9. Clicking a name opens PersonSheet for that `person_id`; closing it keeps the table state.
10. "show everyone at Acme" produces `set_filters` with `op: in`; "also sorted by last activity" adds a sort without touching filters; "reset" restores the default view.
11. "add a Tier column with options 1, 2, 3" creates a `select` field and the column appears without reload.

**v9 gotchas checklist for generated code:** `useTable` not `useReactTable`; `features` option is required; no `getCoreRowModel()`; `sortFn` not `sortingFn`; pin with `'start'`/`'end'`; `enableColumnPinning` not `enablePinning`; call methods on the instance (`row.getValue('x')`, never destructured); `table.state` or the selector, not `table.getState()`; `getIsSomeRowsSelected()` now means "at least one"; types take `TFeatures` first.
