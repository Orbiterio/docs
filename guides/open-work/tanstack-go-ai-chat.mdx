## Phase I build authority

Use [Build Plan — Outcome Chat](/guides/open-work/tanstack-go-ai-chat/build-plan-outcome-chat) as the current implementation contract. Go runs only in `orbiter-backend`; React UI and the TypeScript TanStack AI server route run in `orbiter-frontend`. The TypeScript tools call Go HTTP APIs for persistence. Only outcome intake through explicit SUBMIT is in Phase I; the Xano inventory below includes other surfaces and future work.

The TypeScript harness starts on Gemma, then switches to a second model through OpenRouter after a configurable number of accepted user turns. Compare continuation candidates using real OpenUI buttons and full Submit journeys; Go persists model selection for retry consistency. See the [model bake-off contract](/guides/open-work/tanstack-go-ai-chat/build-plan-outcome-chat#gemma-to-second-model-bake-off).

## Notes

- **Deprecation guard.** Xano `suggestion_request` is superseded by `suggestions.suggestion_request` — see [Suggestion Delivery and Tables](/guides/open-work/suggestion-delivery-and-tables). Do not delete the Xano table until the TanStack AI endpoints are complete and Mark approves.
- **`contacts` stays read-only here** — writes flow through other API groups.
- **Name collision.** Xano "outcomes" (suggestion requests/results) is a different domain from the existing Go `outcomes` feature (`outcomes.investment_theses`). The chat endpoints belong in a new feature (`copilot` proposed) — do not wire them into `internal/features/outcomes`.
- **Historical Xano interview endpoints are stateless** — the four `*/interview` endpoints call OpenRouter and return content without persisting; persistence happens only via the draft/dispatch/context endpoints on `suggestion_request`.
